# Zone-based agent permissions — implementation plan

> **For Claude:** REQUIRED SUB-SKILL: use `superpowers:executing-plans` to work through this task by task.

**Goal:** Make agent memory its own permission instead of a side effect of the file-write checkbox, scope file writes to the agent's own drawer, and move the defaults out of the New-Agent form into the templates.

**Architecture:** Permissions are cut by _zone_ (who owns the data), not by tool. A new grant `pinchy_memory` controls `MEMORY.md` + `memory/`; the existing `pinchy_write` grant keeps its id and controls `workbench/` only. `uploads/` leaves `write_paths` entirely. `build.ts` emits `write_paths` when **either** grant is present, which is what gives a memory-only agent a write tool scoped to nothing but its memory. Full reasoning: [`plans/2026-08-05-agent-permissions-by-zone-design.md`](2026-08-05-agent-permissions-by-zone-design.md).

**Tech stack:** Next.js 16 / React 19, Drizzle + PostgreSQL 17, vitest, Playwright. Agent runtime is OpenClaw via `openclaw.json`, generated by `packages/web/src/lib/openclaw-config/build.ts`.

## Before you start

Read the design record linked above. Then read these three, because every task touches at least one:

- `packages/web/src/lib/openclaw-config/build.ts` — around L615-665, where per-agent tool and path config is emitted.
- `packages/web/src/lib/tool-registry.ts` — `TOOL_REGISTRY` is the **grant** model shown in the Permissions tab. It is _not_ the runtime allowlist: `computeAllowedTools()` derives that from the plugin manifests. `pinchy_ls`/`pinchy_read` are asserted **out** of the registry by test because they are implicit; `pinchy_memory` is the same idea from the other side — a grant with no tool of its own.
- `packages/plugins/pinchy-files/validate.ts` — `validateAccess(..., "write")` checks `write_paths` only, and `assertNoSymlinkEscape` tolerates a not-yet-existing root. This is why granting `MEMORY.md` before the file exists is safe.

**First, in a fresh worktree:** `pnpm install`. Without it nothing below resolves.

**Run test binaries directly, never through `pnpm -C … exec`.** A worktree root is itself a pnpm workspace root with no `node_modules`, so `pnpm exec` resolves through _that_ workspace, goes recursive, and dies with `ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL`. A bare path to the binary works because the install lives in the package. Same trap AGENTS.md documents for the pre-commit hook.

**Inner loop:** `pnpm test:related` (no arguments — it derives the change set from git). It takes no lock and runs only what imports your change.
**Before pushing:** `pnpm test` from the repo root (takes a machine-wide lock, ~55s), plus `pnpm test:scripts`, `pnpm -C packages/web typecheck`, `pnpm format:check`.

`test:related` cannot see a test that reaches your change through a mock or a drift guard that reads the file from disk — and this change trips several drift guards. Do not treat it as the gate.

## Task 2: Gate `memory_search` / `memory_get` on the grant

Today `computeAllowedTools()` takes no arguments and emits the same superset for every agent. That is correct for plugin tools (each plugin gates per-agent in its own config) but wrong for these two: they are OpenClaw built-ins with no Pinchy-side config to gate them, so an agent with no memory gets working recall tools over an empty index. Worse, `memory-core` keys its own `## Memory Recall` prompt section on those tool names being present — so leaving them unconditional would keep instructing memory-less agents to search memory before answering. That is the reported #755 behaviour, and it survives every other fix in this plan.

**Files:**

- Modify: `packages/web/src/lib/tool-registry.ts` (`computeAllowedTools`, ~L291)
- Modify: `packages/web/src/lib/openclaw-config/build.ts` (the call at ~L617)
- Test: `packages/web/src/__tests__/lib/tool-registry.test.ts`

**Step 1: Write the failing test**

```ts
it("emits the memory built-ins only for an agent with the memory grant", () => {
  expect(computeAllowedTools(["pinchy_memory"])).toEqual(
    expect.arrayContaining(["memory_search", "memory_get"]),
  );
  const without = computeAllowedTools([]);
  expect(without).not.toContain("memory_search");
  expect(without).not.toContain("memory_get");
});

it("emits session_status for every agent", () => {
  expect(computeAllowedTools([])).toContain("session_status");
});
```

**Step 2: Run it and watch it fail**

```bash
packages/web/node_modules/.bin/vitest run --root packages/web src/__tests__/lib/tool-registry.test.ts
```

Expected: FAIL — `computeAllowedTools` takes no arguments, and both memory tools are currently unconditional.

**Step 3: Implement**

Split `INTENDED_BUILTIN_TOOLS` into the unconditional part and the memory part, and take the agent's grants:

```ts
const INTENDED_BUILTIN_TOOLS = ["session_status"] as const;
const MEMORY_BUILTIN_TOOLS = ["memory_search", "memory_get"] as const;

export function computeAllowedTools(allowedTools: string[]): string[] {
  return [
    ...getAllPinchyPluginToolNames(),
    ...INTENDED_BUILTIN_TOOLS,
    ...(allowedTools.includes("pinchy_memory") ? MEMORY_BUILTIN_TOOLS : []),
  ];
}
```

Keep the existing block comment above `INTENDED_BUILTIN_TOOLS` and extend it — it documents _why_ each built-in is reachable and is the only place that says `group:memory` does not match these names. Add the new reason: they are now per-agent because the memory-core prompt section keys on them.

In `build.ts`, the call becomes `computeAllowedTools(allowedTools)`. `allowedTools` is already in scope one line above.

**Step 4: Verify**

```bash

```

Expected: green. If `openclaw-config` tests fail on a snapshot of `tools.allow`, update them — they encode the old unconditional contract.

```bash

const agentFilesConfig: Record<string, unknown> = {
  allowed_paths: allowedPaths,
};
const writePaths: string[] = [];

if (allowedTools.includes("pinchy_write")) {
  writePaths.push(workspaceWorkbench);

// Curated templates are generous; a from-scratch agent starts empty. Applied
// here rather than in each of the ~35 template definitions so the rule has one
// home and cannot drift as templates are added.
const CURATED_DEFAULT_GRANTS = ["pinchy_memory", "pinchy_write"] as const;

function withCuratedDefaults(
  templates: Record<string, AgentTemplate>,
): Record<string, AgentTemplate> {
  return Object.fromEntries(
    Object.entries(templates).map(([id, t]) => [
      id,
      {
        ...t,
        allowedTools: [
          ...new Set([...t.allowedTools, ...CURATED_DEFAULT_GRANTS]),
        ],
      },
    ]),
  );
}

export const AGENT_TEMPLATES: Record<string, AgentTemplate> = {
  ...withCuratedDefaults(KNOWLEDGE_BASE_TEMPLATES),
  ...withCuratedDefaults(DOCUMENT_TEMPLATES),
  ...CUSTOM_TEMPLATES, // deliberately NOT wrapped
  ...withCuratedDefaults(ODOO_TEMPLATES),
  ...withCuratedDefaults(EMAIL_TEMPLATES),
  ...withCuratedDefaults(WEB_TEMPLATES),
};
```

## Task 10: Migration

**Files:**

- Create: `packages/web/drizzle/0068_agent_memory_grant.sql`
- Create: `packages/web/drizzle/meta/0068_snapshot.json`
- Modify: `packages/web/drizzle/meta/_journal.json`
- Test: `packages/web/src/__tests__/db/` — a `test:db` spec if the neighbouring data migrations have one; otherwise cover the three rules in a plain SQL-shaped unit test of the predicate

**The SQL** — three rules, idempotent, in this order:

```sql
-- Memory used to ride on the pinchy_write grant (see plans/2026-08-05-agent-
-- permissions-by-zone-design.md). Splitting them would silently revoke memory
-- from every agent that has it today, so rule 1 is not optional.

-- 1. Agents that HAVE memory today keep it. Without this they would lose access
--    to memory files they have already written.
UPDATE agents
SET allowed_tools = allowed_tools || '["pinchy_memory"]'::jsonb
WHERE allowed_tools @> '["pinchy_write"]'::jsonb
  AND NOT (allowed_tools @> '["pinchy_memory"]'::jsonb);

-- 2. Every agent from a curated template, applying the new default policy
--    retroactively. `custom` is the from-scratch template and is excluded.
UPDATE agents
SET allowed_tools = allowed_tools || '["pinchy_memory"]'::jsonb
WHERE template_id IS NOT NULL
  AND template_id <> 'custom'
  AND NOT (allowed_tools @> '["pinchy_memory"]'::jsonb);

-- 3. Personal agents (Smithers) carry no template_id, so rule 2 misses them.
UPDATE agents
SET allowed_tools = allowed_tools || '["pinchy_memory"]'::jsonb
WHERE is_personal = true
  AND NOT (allowed_tools @> '["pinchy_memory"]'::jsonb);
```

**The snapshot.** `scripts/check-drizzle-snapshots.mjs` runs in the pre-commit hook and requires a companion snapshot for every staged migration. This migration changes no schema, so the snapshot is a copy of the previous one with fresh ids — the same thing migration 0032 did (verified: `0031_snapshot.json` and `0032_snapshot.json` are byte-identical apart from `id`/`prevId`):

```bash
cd packages/web/drizzle/meta
python3 - <<'PY'
import json, uuid
s = json.load(open("0067_snapshot.json"))
s["prevId"] = s["id"]
s["id"] = str(uuid.uuid4())
json.dump(s, open("0068_snapshot.json", "w"), indent=2)
PY
```

Then append the journal entry, mirroring the shape of `idx: 67`. Use a `when` timestamp greater than 1785873258121.
